# Source review sequence

Use this sequence within the assigned topic and source boundary, after establishing scope and before writing the review record. For supplied-fact reviews, use the given evidence and mark missing traces rather than inventing source access.

1. **Trace behavior first.** Follow the relevant entry points through guards, state/resource changes and observable results, including failure and early-return paths. Check where a claimed safeguard actually takes effect and how its result reaches callers; its presence alone does not establish enforcement. Compare contract assertions in tests with the paths inspected. Record material paths left unassessed in coverage, rather than inferring completeness from files read or passing checks.
2. **Assess maintenance candidates against consumers.** After the behavior pass, examine concrete reading/change costs. For a proposed removal or consolidation, inspect production callers, method-value/interface uses and meaningful test consumers, and identify the responsibility that must remain. Distinguish helper-only tests from tests checking another supported behavior, including negative controls; identify the regression that use would detect. Absence of production calls alone does not establish redundancy. Keep supported small maintenance findings even when runtime behavior is correct.
3. **Reconcile before grading.** Recheck each candidate's consequence and proposed correction against that trace, including evidence that weakens the claim. Retain the supported core, reject contradicted claims, and keep unresolved assumptions ungraded. Assign the primary topic by the demonstrated consequence; a second description of the same API-surface cost is not a separate local effect. Deduplicate causes, qualify coverage and strengths, then populate the record and render. Formatting and arithmetic checks do not validate discovery or source claims.

Use existing record fields for evidence, decisions and coverage; a separate per-file log or additional report is unnecessary.
