# Go quality build

Status: `go-package-boundaries` is implemented and behaviorally evaluated. Its [baseline](../../tests/go-quality-build/results/2026-10-01-package-boundaries-baseline/README.md) and [skill-on evidence](../../tests/go-quality-build/results/2026-10-01-package-boundaries-skill-on/README.md) show a bounded improvement on a medium-service ownership decision after revision, with no observed package overbuilding in the control cases. Automatic routing and Codex/OpenCode runtime loading remain unverified; see the [design record](../../docs/go-quality-build/README.md).

The standalone `go-package-boundaries` skill applies when Go work adds or moves responsibilities, changes packages, or changes import direction. It supports libraries, CLIs, services, and workers. A local arithmetic or expression fix does not need it. Package maps illustrate choices without prescribing a layout.

`go-api-contracts` is implemented and behaviorally evaluated on [bounded cases](../../tests/go-quality-build/results/2026-10-01-api-contracts-skill-on/README.md). It applies to exported APIs and supported external CLI, wire/file and error contracts; private helper fixes without an established external contract do not need it. Its first-pass source case fixed a zero-value regression, and targeted revised cases checked v2 migration and CLI compatibility. Final-revision source behavior and automatic routing remain unverified. The separate `go-quality-review` package can independently review completed work; this package does not grade itself.

`go-interfaces-and-composition` is implemented and behaviorally evaluated with [revision-specific evidence](../../tests/go-quality-build/results/2026-10-01-interfaces-composition-skill-on/README.md). It covers abstraction choices, instance dependencies, construction and host-owned lifecycle. The final lifecycle trial improved Architecture from baseline B to A by joining every started run before resource release, including after one error; its reconciled Testing grade is C+ because two regression tests are missing. Earlier protocol and tenant trials stayed Architecture A/Testing B, and an arithmetic control skipped the skill. The zero-value skill-on trial was blocked by automatic approval review, and automatic routing remains unverified. See the [independent task review](../../tests/go-quality-build/results/2026-10-01-interfaces-composition-skill-on/task-review.md) and design record for limits.

`go-behavior-tests` is implemented and evaluated on [five matched cases](../../tests/go-quality-build/results/2026-10-01-behavior-tests-skill-on/comparison.md). It chooses meaningful cases, independent assertions and the consumer/process/host boundary that establishes a supported promise. Revision 1 closes partial-failed-duplicate retention and callback-error/successful-release test gaps: blind CLI/worker Testing improved from B to A+, while already-strong codec/service cases were preserved and a comment-only control skipped it. The [independent promotion review](../../tests/go-quality-build/results/2026-10-01-behavior-tests-skill-on/task-review.md) supports unchanged guidance after an audit-only correction. These are bounded task outcomes, not general A-grade guarantees; automatic routing, Go 1.22 execution and broader platform/runtime effectiveness remain unverified.

`go-test-isolation` is implemented and evaluated on [five matched cases](../../tests/go-quality-build/results/2026-10-01-test-isolation-skill-on/comparison.md). It controls dependency fidelity, fixture ownership, process state, asynchronous events and cleanup. Revision 1 removes a focused-subtest independence defect (Testing B to A+) while retaining deterministic persistence checks. Strong environment/HTTP/worker baselines remain A+ and the pure control skips isolation. The [independent promotion review](../../tests/go-quality-build/results/2026-10-01-test-isolation-skill-on/task-review.md) supports unchanged-byte promotion. These bounded results do not establish broader schedule/platform effectiveness or automatic routing.

## Local use and installation

From the repository root, Claude Code can load this package with `claude --plugin-dir ./plugins/go-quality-build`; its skills are `/go-quality-build:go-package-boundaries`, `/go-quality-build:go-api-contracts`, `/go-quality-build:go-interfaces-and-composition`, `/go-quality-build:go-behavior-tests`, and `/go-quality-build:go-test-isolation`. Through the repository marketplace, install `go-quality-build@joebartels-skills` using the same harness commands documented in the [repository guide](../../README.md).

Codex uses the root portable manifest and the repository's `.agents/plugins/marketplace.json`. Select the applicable build skill after loading the package. OpenCode v2 uses the skills source in the root `opencode.json`; for another working directory, use the absolute path to this package's `skills/` directory. Development does not require global installation.

Runtime instructions are canonical under `skills/`; fixtures and evaluation reports remain outside the package. The guidance and examples are newly written from the approved design and audited decision criteria; no upstream source text or code is copied. Upstream provenance and copy/adapt/omit decisions are in the [architecture audit](../../docs/go-quality-build/source-audit.md) and [testing audit](../../docs/go-quality-build/testing-source-audit.md).
