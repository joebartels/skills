# Native pgx and PostgreSQL

Use the installed pgx version and the application's existing pool/transaction APIs. A native pgx.Tx is not a database/sql Tx: Begin's context controls the begin command and does not arrange automatic rollback when canceled. Register owned cleanup immediately, including before QueryRow.Scan can fail. If the caller may already be canceled, required rollback needs a live, bounded cleanup context; preserve metadata when the contract requires it and release that scope. Keep original and required cleanup failures inspectable. Treat pgx.ErrTxClosed as routine after finalization; inspect other failures against the actual API.

Read QueryRow errors through Scan. Consume/close Rows before reusing the native connection, then inspect Err; Next returning false closes pgx Rows automatically. Check the commit result, including ErrTxCommitRollback for an aborted PostgreSQL transaction. A returned commit transport error is not proof about durable effects. A borrowed transaction's owner retains finalization. Native Tx.Begin uses savepoints; it is not an independent durable commit.

PostgreSQL Read Committed can take a different snapshot for each statement. Identify the observed rows that later writes must protect; do not attach or modify rows merely because they now match a broader predicate when the operation only processed an earlier set. Choose row locks, conditional writes, constraints or stronger isolation for the actual invariant. Serialization failures require repeating the complete transaction and its decision-making, not one failed statement; keep attempts bounded and external effects safe. Confirm native error codes/types instead of parsing human messages. Do not claim PostgreSQL behavior from a pgx mock alone.

Primary sources: [pgx transaction API](https://pkg.go.dev/github.com/jackc/pgx/v5#Tx), [BeginTx](https://pkg.go.dev/github.com/jackc/pgx/v5#Conn.BeginTx), [PostgreSQL isolation](https://www.postgresql.org/docs/current/transaction-iso.html), [serialization failures](https://www.postgresql.org/docs/current/mvcc-serialization-failure-handling.html).
