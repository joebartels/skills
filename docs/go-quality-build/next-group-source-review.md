## Adapt or omit before authoring

These are proposed dispositions, not accepted runtime text. **Copy: none at this stage.** If implementation selects any passage or example, complete the section-level import audit and execute the applicable example before retaining it.

| Inspected material | Disposition and local decision owner |
| --- | --- |
| Samber context entrypoint: trigger, parent propagation, derived cancel ownership | **Adapt — context.** Trace the caller's cancellation and remaining deadline through blocking calls. A derived context may be appropriate; requiring the identical context object everywhere is unnecessary. Preserve supported API contracts. |
| Samber cancellation reference: nested deadlines and periodic cancellation observation | **Adapt — context.** Choose observation points from the operation's responsiveness promise. Its `processItems` example returns on one error after requesting cancellation without observing all spawned completions; do not carry that example into owned-work guidance unchanged. Joining belongs to concurrency. |
| Samber cancellation reference and spf13 detached-work example | **Adapt — context/concurrency.** Retain detachment only for an explicit lifetime requirement. Add a new bound and completion owner. `WithoutCancel` removes the parent's deadline as well as cancellation; it alone supplies neither a time limit nor evidence that the work completed. [Context documentation](https://pkg.go.dev/context#WithoutCancel). |
| Samber `AfterFunc` resource-release example | **Adapt — context/concurrency.** Establish callback ownership and synchronization with users of the resource. Stopping the callback does not wait for an already-started callback; do not infer safe release from cancellation alone. [AfterFunc documentation](https://pkg.go.dev/context#AfterFunc). |
| Samber HTTP propagation reference | **Adapt — context.** Keep request-to-client propagation and response lifetime explicit. A context argument enables cooperation; it does not prove every driver or remote operation stops immediately. Repair schematic return signatures and omitted ownership if an example is retained. [Database cancellation](https://go.dev/doc/database/cancel-operations). |
| Samber values/tracing reference | **Adapt narrowly — context.** Keep request metadata separate from configuration and dependencies, with collision-resistant keys. **Omit** tracing middleware, header recipes and telemetry dependencies from this group; those decisions belong to telemetry/security. |
| Samber concurrency entrypoint and spf13 concurrency section | **Adapt — concurrency.** Keep visible state, capacity, exit and completion ownership. **Omit** universal channel preference, pointer-send prohibition, worker-pool replacement and mandatory `errgroup`/leak-detector dependencies. Choose a mechanism from the actual invariant and lifetime. |
| Samber channels/select reference | **Adapt — concurrency.** Cancellation must reach operations that can otherwise remain blocked; not every `select` needs a context case. Closing requires a designated owner that knows all sends are finished, which may be a coordinator. **Omit** automatic panic recovery and fixed buffer-size rules. Follow the actual failure and queue contract. [Pipeline guidance](https://go.dev/blog/pipelines). |
| Samber sync-primitives reference | **Adapt — concurrency.** Retain ordinary locks, correctly registered work and observable completion. `sync.Map` has specific use cases; read-heavy alone is insufficient. Independent atomics do not establish a compound invariant. **Omit** pooling, deduplication and unmeasured speed claims from the entrypoint. [Sync documentation](https://pkg.go.dev/sync#Map). |
| Samber pipelines reference and both collections' `SetLimit` examples | **Adapt — concurrency.** Inspect blocked receives, sends and admission, including upstream non-cooperation and early consumers. `errgroup.Go` can block on a configured limit; its associated context does not itself provide cancellation-aware admission. Choose draining/error semantics first. **Omit** unrelated reactive libraries and iterator tutorials. [Errgroup documentation](https://pkg.go.dev/golang.org/x/sync/errgroup#Group.Go). |
| Uber goroutine, mutex and channel references | **Adapt — concurrency.** Preserve separate stop/completion observations and hidden synchronization state. Derive capacity from handoff/queue behavior rather than a zero-or-one restriction. Retain leak detectors only when justified by the project. |
| Google synchronous-function and lifetime guidance | **Adapt — concurrency.** Prefer a direct synchronous operation when concurrency serves no required behavior. Keep any required concurrency close to its owner. Google-specific approval paths, internal packages and conventions do not become collection requirements. |
| spf13 spec-review procedure | **Adapt — authoring process.** Review concrete missing failure paths, conflicting contracts and unnecessary abstractions. **Omit** personas, fixed harness paths, automatic delegation and mandatory neighboring skills; independent code review already has its own local owner. |
| Newer helpers and timer recipes across sources | **Adapt — each decision owner.** Check supported language/module/toolchain behavior before selecting helpers. `WaitGroup.Go` requires Go 1.25; older supported code needs valid alternatives. Existing references already distinguish timer behavior. Modern syntax is not a reason to raise a project's minimum. [WaitGroup.Go](https://pkg.go.dev/sync#WaitGroup.Go), [local performance decisions](../../plugins/go-quality-review/skills/go-performance-and-resource-management/references/performance-decisions.md). |
| Tool lists, auto-audit modes and upstream skill cross-references | **Omit — packaging/process.** The runtime guidance must work through each supported harness's available file and execution tools. No imported orchestration, automatic configuration or dependency on absent upstream skills. |

## Consequences for the plan

Keep the proposed context and concurrency ownership split. Write compact decision procedures with concrete conditions, visible owners, failure paths and verification observations. Retain only guidance that changes a useful decision; conditional references need an actual use. Do not create a general Go encyclopedia or replace one blanket rule with another.

The [next-group plan](next-group-plan.md) carries the collection-wide authoring requirements and a bounded portability study. No source reading establishes reuse consistency: final candidate bytes still need matched author outcomes, controls, native harness loading evidence and explicit limits.
