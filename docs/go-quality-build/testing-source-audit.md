Reviewer criteria (unchanged [Testing decisions](../../plugins/go-quality-review/skills/go-testing/references/testing-decisions.md)): R1 behavior/assertions; R2 structure; R3 doubles/integration; R4 isolation/concurrency; R5 broader inputs/measurement.

Primary documentation checked 2026-10-01:

- G1: [testing](https://pkg.go.dev/testing): tests/examples, subtests, Cleanup, TempDir, Setenv, FailNow, T.Context versions. Cleanup waits for descendants; Fatal/FailNow belong to the test goroutine; Setenv forbids parallel ancestors.
- G2: [synctest](https://pkg.go.dev/testing/synctest): stable Test in Go1.25, bubble time/goroutine scope; external I/O does not become controlled virtual time.
- G3: [race detector](https://go.dev/doc/articles/race_detector): executed paths only, run where concurrent behavior matters.
- G4: [net/http/httptest](https://pkg.go.dev/net/http/httptest): recorder versus actual local HTTP client/server boundary.
- G5: [subtests](https://go.dev/blog/subtests): parent lifetime and parallel scheduling. Combine with version-aware loop variables, not a universal capture recipe.
- G6: [fuzzing](https://go.dev/doc/security/fuzz/): deterministic targets and independent, useful properties.
- G7: [Google testing guidance](https://google.github.io/styleguide/go/decisions#testing) and [Uber test tables](https://github.com/uber-go/guide/blob/master/style.md#test-tables): concrete diagnostics and table cases where shared setup helps. Their local conventions are context, not universal acceptance criteria.
