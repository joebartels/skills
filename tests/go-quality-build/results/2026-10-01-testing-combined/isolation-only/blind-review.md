# Independent review of the anonymized indexer changeset

Reviewed only the supplied `original` → `candidate` directories, their identical README contract, and the three supplied review skills and local decision references. No author report, expectation file, other candidate, repository workspace, or delegated review was consulted. The supplied directories are the revision boundary; no Git revisions were supplied. Paths below are relative to `candidate` unless marked otherwise. Source was not repaired or mutated. All deliberate regressions and the additional redirect probe exist in separate disposable copies.

The requested evolution is a standard-library Go1.22 library plus a CLI: accepted-prefix CSV application, validated atomic HTTP snapshots, an owned sequential refresh lifecycle, and actual `put`/`apply`/`watch` process behavior. `Put` and `Get` production bodies are unchanged; the previous new-operation bodies returned `ErrNotImplemented`.

Two independently actionable findings are reported: F1 is the production redirect-policy defect, owned by Correctness & Compatibility; F2 is the regression-test gap that permits F1, owned by Testing. F1 and F2 require different corrections (request handling versus assertions). Architecture mentions F1 as a related local correctness defect; it does not count it as a separate design issue.

## Testing — B

Scope: Supplied `original` → `candidate` library and CLI changeset, including newly requested regression tests. Module declares `go 1.22`; checks executed with Go1.26.5 on darwin/arm64 and `GOTOOLCHAIN=local`.
Coverage: Assessed assertions and failure paths for existing put/get compatibility, independent roots, CSV ordering/quoting/duplicates and accepted-prefix effects, HTTP status/decode/validation/read/fetch/publication rejection, body ownership, POSIX open-reader snapshots, caller context and real HTTP cancellation, interval/cleanup/error lifecycle behavior, and built-command exits/stdout/stderr/startup/signal handling. Inspected resource cleanup, goroutine ownership, table capture under the module's language version, and process deadlines. Exercised full tests, three shuffled race runs, and three focused deliberate-regression checks. No new fuzz target or benchmark was included; neither is needed to substantiate the findings. Redirect behavior has a demonstrated missing assertion (F2).
Rationale: One moderate testing gap selects B. It leaves a plausible HTTP response path insufficiently checked, while other status, validation, state-retention, real-process and lifecycle contracts have useful assertions. The gap does not make the whole Refresh contract effectively unverified. No minor, major or critical testing finding is counted. Passing tests, number of cases, and coverage percentage were not used as a quality score.
Finding counts: critical=0, major=0, moderate=1, minor=0

## Correctness & Compatibility — B

Scope: Supplied `original` → `candidate` Go1.22 library/CLI changeset. The supported contract is the supplied README, including preserved exported signatures and existing arbitrary-text Put semantics, new CSV prefix effects, one-GET/status-200-only atomic refresh, sequential owned lifecycle, and command process conventions. Checked on darwin/arm64 with Go1.26.5.
Coverage: Compared all changed production bodies and affected consumers/tests to the original. Traced valid/empty/invalid input, wrapped error identities, retained state on partial/error paths, serialization order/ownership, same-directory replacement, timer scheduling, cancellation/cleanup/release order, caller context, signal handling, and idle-connection release. Function signatures are unchanged. Assessed minimum-version-sensitive language/library usage and ran the standard-version vet check. Exact Go1.22 runtime and Windows execution remain unverified. Default redirect behavior is the one confirmed changed-operation mismatch (F1).
Rationale: One contained moderate correctness/compatibility issue selects B. The default client redirect policy accepts an initial 302 and performs a second GET, contradicting the one-request/non-200 rejection contract and replacing prior bytes. The verified impact is confined to redirected Refresh/watch requests; the final payload still undergoes ordinary content validation and atomic publication. There is no evidence of broad corruption, hang, incompatible signature or loss of unrelated operations, so this is not classified as a major/systemic failure. No minor, major or critical correctness finding is counted.
Finding counts: critical=0, major=0, moderate=1, minor=0

Good

- [C-G1] `index.go:21` and `index.go:42` preserve existing Put/Get bodies. New `ApplyCSV` at `index.go:51` reads and validates each record before calling the existing atomic Put, returns at the first read/validation/write error, wraps causes with `%w`, and leaves earlier accepted rows in place. Exact arbitrary Put text (including empty, whitespace and NUL), CSV quoted text and retained-prefix assertions execute successfully (`index_test.go:27`, `index_test.go:60`, `index_test.go:71`, `index_test.go:103`). Consumer function-value assignments also compile (`index_test.go:17`).
- [C-G2] `refresh.go:33` reads the full response before publication; `json.Unmarshal` at `refresh.go:38` rejects trailing data and wrong top-level types, and `refresh.go:41` rejects null while permitting a non-nil empty array. Every record is validated before serialization/publication (`refresh.go:44`), retaining ErrInvalidRecord identity. The snapshot test confirms original text/order/duplicates and `[]\n`; rejection and late-reader-error cases confirm exact old-byte preservation. Body closure at `refresh.go:29` is exercised on success and the tested rejection/publication paths.
- [C-G3] `refresh.go:59` creates a temporary file in the destination directory, writes/closes it before rename, and removes unused temps. The executed POSIX old-reader/new-reader assertion proves the old snapshot survives replacement and a later read sees the complete new snapshot. Permission and directory-target publication failures retain state, and a deliberately in-place replacement fails the old-reader assertion.
- [C-G4] `serve.go:15` rejects invalid intervals before taking release ownership. Valid runs use the caller context, synchronous callbacks and completion-relative timers (`serve.go:18`–`serve.go:31`); release occurs only after callback return and joins errors. Executed tests verify already-canceled contexts, ordinary cancellation returning nil, a callback's context error remaining observable, combined error identities, non-overlap, completion-relative delay, cancellation during interval and independent runs. Race checking passed for these exercised paths.
- [C-G5] `cmd/indexer/main.go:23` preserves put's positional grammar, including arguments beginning with `-`; apply uses stdin; watch validates required startup values, owns signal cancellation and an HTTP transport, and closes idle connections through Serve's post-callback release (`cmd/indexer/main.go:63`–`cmd/indexer/main.go:76`). Built-command tests verify the requested output/exit conventions and recurring snapshots before cancellation. Main still emits a diagnostic to stderr and exits 2 on error (`cmd/indexer/main.go:80`).

Bad

- [F1][moderate][introduced] `refresh.go:25` invokes the supplied `http.Client.Do` with its default redirect behavior and then checks only the final response at `refresh.go:30`. An endpoint returning 302 with a Location that responds 200 is followed automatically. The finite disposable `TestReviewRedirectRejection` reproduces `requests=2`, `err=<nil>`, and prior destination bytes replaced with `[{"key":"alpha","text":"new"}]\n`. The README states that Refresh makes one GET and accepts only status 200; under that explicit one-request reading, the original 302 should be rejected and the prior bytes retained. The command constructs an ordinary client at `cmd/indexer/main.go:66`, so it exposes the same behavior. Primary remediation owner: Correctness & Compatibility.

Suggested changes

- [F1] Enforce the one-GET/non-200 response boundary by preventing automatic redirect following while preserving the supplied client's configured transport/context/other behavior and avoiding mutation of the caller's client. Ensure the initial 3xx response is acquired, closed and rejected before publication. Verify with the F2 regression case: one GET, rejection and byte-identical prior destination; retain the existing direct-200, rejection, cancellation and process checks.

Limits: The redirect finding uses the README's explicit network-request/status boundary, not an invented prohibition on unknown JSON fields or a durability requirement. The probe uses a real `http.Client` and a counting RoundTripper, so redirect handling is exercised without a remote endpoint. It exited 1 with the specific violated assertions; it is an additional reproduction, not a failing candidate test. The supplied full tests and three shuffled race runs exited 0 with local listeners enabled. `go vet -stdversion ./...` exited 0, but it is not a substitute for running Go1.22. No remote fetch, toolchain installation, Windows replacement test, disk-fault injection or crash-durability test was performed. The README does not promise crash durability or all-or-nothing CSV semantics. Source signatures and modules were preserved, and there is no consumer versioning evidence beyond the supplied README contract. Detailed facts are in `checks.json`.

## Architecture & Design — A+

Scope: Supplied `original` → `candidate` integrated production changeset, a small Go1.22 file-backed index library and host-owned CLI. Implementing ApplyCSV/Refresh/Serve and composing watch changes production structure and lifecycle ownership, so Architecture is applicable.
Coverage: Assessed the two-package responsibility split, unchanged concrete exported APIs, function/io.Reader/http.Client dependency boundaries, validation/publication ownership, compact JSON Record representation, context/error propagation, synchronous callback lifetime, signal ownership and HTTP transport cleanup. Followed file bytes and response-body ownership through the library and command. No additional service/persistence/package layering or interface hierarchy was assumed. Full tests, race/shuffle checks and deliberate publication/lifetime/error mutations provide finite evidence for the observed safeguards. Go1.22 runtime and Windows execution are limits, not evidence of an architectural failure.
Rationale: No actionable architectural root cause was found. Two independent safeguards support A+: (1) complete snapshot validation followed by same-directory atomic publication protects current and pre-opened reader state; (2) synchronous lifecycle ownership with host-owned cancellation and joined callback/release errors protects resource release and observable failure after cooperative cleanup. The full suite verifies both risks, the in-place publication mutation is rejected, and separate premature-release and lost-release-error mutations are rejected. These controls address independent data-boundary and resource-lifetime risks rather than duplicating a single safeguard. The local redirect correctness defect F1 is separately graded; its correction does not require new packages, interfaces or a lifecycle redesign.
Finding counts: critical=0, major=0, moderate=0, minor=0

CSV is intentionally incremental while Refresh validates the whole fetched snapshot before publication. This puts each operation's state-transition contract at the appropriate boundary and avoids imposing transactional semantics on CSV. Prefix and rejected-snapshot tests execute successfully.
- [A-G2] `refresh.go:18`–`refresh.go:55` accepts an explicit context, concrete configurable client, endpoint and output path, and owns only each acquired response body. `publish` remains a private cohesive filesystem operation (`refresh.go:59`). - [A-G3] `serve.go:14` exposes the minimal callback/release protocol required by lifecycle consumers, with no hidden global state or detached workers. Two production packages remain proportionate to the specified scope.
