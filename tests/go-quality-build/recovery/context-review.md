## Confirmed gap and narrow correction

Both HTTP outputs close an already-closed body when `Client.Do` returns a response and redirect-policy error ([baseline patch](patches/context-development-baseline.patch), lines 49–55; [guided patch](patches/context-development-guided.patch), lines 49–54). `Client.Do` already closes that error response's body; repeated `io.Closer.Close` behavior is unspecified. The extra close can produce an unrelated error or repeat a side effect. [Client.Do documentation](https://pkg.go.dev/net/http#Client.Do), [io.Closer documentation](https://pkg.go.dev/io#Closer).

The authorized [redirect ownership diagnostic](../go-context-and-deadlines/evals/controller-probes/redirect-ownership_test.go) was added **after inspection**. In disposable copies, `rtk proxy go test -run '^TestRecoveryRedirectBodyOwnership$' -count=1 -timeout=10s ./...` fails both outputs on Go 1.26.5 and 1.22.12: `closes=2`, retained policy error, and an exposed second-close error. Environments used `GOWORK=off`, the recovery cache/toolchain paths, `GOTOOLCHAIN=local` or `go1.22.12`, and `CGO_ENABLED=0`. Original author trees were untouched.

Retain this one diagnostic and the revision-1 failures. A short reminder to follow the actual dependency's body ownership semantics is justified; keeping a scope alive does not imply ownership of every returned resource. A fresh revised-guidance author should omit the extra close and preserve all frozen checks. This is a shared gap, not evidence that revision 1 caused a regression.
